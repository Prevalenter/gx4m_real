# GX7＋GX4M 关节控制

单页 Viser 控制台，只控制 GX7 右臂 J1–J7。GX4M 手和腕部相机保留在模型中，手指固定为 `config/initial_pose.json` 的姿态，不连接其硬件。

## 安装与启动

在仓库根目录执行：

```bash
bash apps/control/setup.sh
bash apps/control/run.sh
```

打开 **http://127.0.0.1:8086**。默认使用真实数据：启动时只读采样一次真机关节，相机预览默认选择真实相机；不会自动使能电机。读取失败会明确报错并隐藏机器人模型，不会用预设角度冒充反馈。只有点击“连接真机（使能）”才进入控制。

需要完全模拟运行时，显式使用 `bash apps/control/run.sh --simulate`。这时连接按钮明确标为“连接模拟机械臂”，相机预览选择模拟画面。

1. 移动 7 个滑块编辑目标角度，单位为度；此时模型和机械臂不移动。
2. 点击“发送目标”提交整组角度。模型按实际反馈更新，下面的表格显示实际角度和已提交目标。
3. “保持当前位置”取消尚未完成的目标，改为保持当前实测位置，同时把滑块同步到该位置。
4. “断开”释放连接；终端 Ctrl+C 会清理控制线程和 Viser 服务。

`run.sh` 从任意工作目录均可运行。安装脚本只创建独立的 `gear3_control` Conda 环境并安装依赖，不连接机械臂，不修改感知环境。Python 入口也可直接运行：

```bash
conda activate gear3_control
python apps/control/app.py
```

## 真机模式

```bash
bash apps/control/run.sh --real
```

`--real` 与默认启动方式等价。启动的只读查询会短暂打开 CAN 并在读完后关闭，但不改变电机状态。只有点击“连接真机（使能）”才使能右臂并启动控制线程。连接先读取实测位置，以该位置初始化 PVT 目标；不会自动回零或前往初始姿态（`config/initial_pose.json`）。断开或退出会调用原 SDK 的停止流程，停止线程并失能电机；这与“保持当前位置”不同，断开前应托住需要支撑的机械臂。

`config.yaml` 的默认值来自源项目配置：适配器序列号 `31F1000632C`，CAN1／通道 0。请按实际接线修改；指定序列号不存在时直接报错，不回退到其他适配器。页面滑块和发送校验采用 `gx7_right.yaml` 的硬件限位，电机 1–7 明确映射到模型 `joint1`–`joint7`。角度在驱动内部为弧度。

默认底层控制 100 Hz，目标和界面更新约 30 Hz，速度上限 0.25 rad/s，力矩比例上限 0.85，每次目标与实测关节的差值限制为 0.08 rad。保留底层软限位、电机故障保护及 CAN 超时处理；反馈超过 0.3 秒未更新时进入故障并停止驱动，需断开再连接。

## 在 Viser 中校准关节方向与零点

“关节方向与零点补偿”面板支持逐关节选择 `+1` / `-1` 并填写零点偏移（度），映射为：

```text
模型角度 = direction × 电机反馈角度 + offset_deg
电机目标 = direction × (模型目标 − offset_deg)
```

1. 保持未连接状态。若已经连接，先支撑好机械臂再断开；断开会失能。
2. 点击“只读采样真机关节（不使能）”，读取当前七个电机角度；该按钮独立于控制模式，模拟控制模式也读取真实硬件，不会返回预设值，不会使能、失能、清零或修改电机控制模式。不要同时运行其他占用该 CAN 适配器的程序。
3. 调整方向和零点，三维模型实时预览，表格同时显示原始电机角度与模型角度。“关节数据来源”明确标注真机采样时间、真机实时反馈或模拟反馈。采样是单次的，移动实物后需再次采样；失败时会明确标记，不能把旧数据当作新反馈。修改补偿本身不会让实物运动。
4. 确认后由你点击“保存补偿（重启后生效）”，写入 `apps/control/joint_compensation.yaml`。编辑不会自动保存；“恢复启动时补偿”只恢复界面，不覆盖已保存文件。
5. 停止程序再重新启动，加载已保存的补偿。尚未应用的预览会阻止连接和发送目标；连接期间禁止编辑、采样或保存补偿。

默认所有方向为 `+1`、偏移为 `0`，不改变原有行为。补偿只作用于机械臂 J1–J7，不改变基座位姿或固定的手指姿态。控制台目标和模型显示采用补偿后的坐标，发送前反算为电机原始坐标；原有电机限位、限速、保持当前位置逻辑不变，模型目标滑块范围由硬件限位映射得到。录制、回放和同步采集中的关节值仍为原始电机弧度，不对旧录制文件重复应用补偿。

补偿文件路径由 `config.yaml` 的 `joint_compensation` 指定；声明的文件不存在或配置非法会直接报错，不会悄悄忽略补偿。

## 相机画面预览

Viser 的“相机 RGB 预览”面板显示相机图像。启动程序不会自动占用相机；点击“打开相机预览”后才打开，点击“关闭相机预览”或退出程序时释放。相机在独立线程采集，网页画面最多更新约 10 Hz，不阻塞机械臂更新循环。

预览源独立于机械臂是否连接，默认“真实相机”，点击按钮即可查看 Orbbec 实拍图，不需要使能机械臂。可用 `--camera-device-index` 选择设备；`--simulate` 或下拉框选择“模拟画面”时显示明确标记的合成图像。相机按钮不会使能机械臂。不要同时用其他程序打开同一台相机。回放录制仍遵循原有规则：模拟机械臂模式录制合成图像，真机模式录制真实图像。

开启无力录制或回放同步采集时，程序先释放独立预览，再复用采集线程的 RGB 帧，不会第二次打开相机。页面同时显示“相机 RGB”实时画面和“已保存的录制帧”：后者只在 PNG 和索引写入成功后更新，并展示该帧时间戳、对齐有效性、前后反馈时间差及七个实测关节角（原始电机弧度）。两幅画面可能因写盘延迟略有不同，但录制帧的图像和关节值始终来自同一条索引。结束后保留最后一张录制帧，可再次点击预览按钮打开实时画面。实时图像超过 2 秒未更新或相机出错时隐藏旧实时画面并显示状态；独立预览故障不会改变机械臂状态。

真机预览和同步采集的相机 SDK 均在独立进程中运行，避免相机初始化阻塞机械臂的 Python 控制线程。RGB 帧保留子进程采集时的主机单调时钟时间戳，再传回主进程用于关节对齐。相机异常、启动超时或关闭时会回收子进程。

2026-10-29 实机只读诊断发现，同进程打开相机时 CAN 查询间隔曾达到 1233 毫秒；改为独立进程后，连续两次打开相机并采集 120 帧，最大查询间隔为 12.8 毫秒，CAN 查询无超时。诊断未使能机械臂；该结果验证相机启动对通信调度的影响，不代表完整的带出力录制验收。电机反馈的 `0xD` 是电机报告的通信故障状态，即使当前查询能收到角度也可能保留；应用仍按故障停止，不屏蔽该状态。

## 无力录制与位置回放

启动方式不变，在页面“无力录制与位置回放”中操作：

1. 连接后先托住机械臂，点击“开始无力录制”。默认同时采集 RGB 与实测关节，先确认相机可用，再将 J1–J7 失能；可以手动拖动，页面模型跟随实测位置，并同时预览实时图像和已保存的录制帧。驱动器必须持续供电，CAN 必须保持连接。只需要关节轨迹时，先关闭“无力录制时同步采集”。
2. 点击“停止并保存录制”，将约 30 Hz 的关节反馈和相对时间保存为 JSON。默认路径为 `control/runtime/recordings/joints_时间戳.json`，也可修改保存路径；已有文件不会被覆盖。停止后继续保持失能。
3. 保存路径会自动填入“回放文件路径”。也可以填入以前保存的 JSON 文件绝对路径。点击“开始位置回放”，恢复出力，先限速移动到录制起点，再按时间顺序插值回放。结束后保持最后位置。
4. “回放倍率”范围为 0.1–2 倍；程序会按原有 0.25 rad/s 速度上限自动降低实际倍率。实测位置落后时暂停推进轨迹时间，因此回放用时可能比录制更长。
5. 点击“停止回放并保持”可中止回放；失能状态下点击“保持当前位置”会恢复出力并保持当前实测姿态。

正常断开、Ctrl+C 或反馈故障会尝试保存已录制的数据；进程被强制杀死或掉电时，尚未保存的数据会丢失。JSON 使用 `joint1`–`joint7` 顺序、弧度和秒，加载时会校验关节顺序、角度限位、有限数值和时间递增。一次有效回放至少需要两帧。

失能采集进入时仅失能一次，随后使用 SDK 的反馈查询指令（CAN ID `0x7FF`，命令 `0xCC`）持续读取编码器反馈，CAN 收发统一在底层控制线程执行；失能期间不发送位置目标或使能指令。恢复出力前重新查询当前位置并设为保持目标。该路径需在实机上确认长时间采集及手动拖动时的角度更新。模拟模式支持完整录制、保存、加载和回放流程，但不会自行生成手动拖动动作。

模型使用本仓库 `asset/gx7_right/urdf/gx7_right_gx4m_cam_xl330.urdf`，基座和固定手指姿态取自 `config/initial_pose.json`。默认仅监听本机，地址和端口可在 `config.yaml` 修改，亦可通过 `--config` 指定另一份配置。

## 录制与回放时同步采集 RGB 与关节位置

页面“录制与回放同步采集 RGB 与关节位置”中的“无力录制时同步采集”和“回放时同步采集”默认开启。更新后先运行一次安装脚本，补齐相机 SDK；启动命令不变：

```bash
bash apps/control/setup.sh
bash apps/control/run.sh --real
```

点击“开始无力录制”或选择关节轨迹并点击“开始位置回放”，程序先打开 Gemini / Orbbec 相机并预热，确认有 RGB 图像后才开始录制或运动。相机默认设备索引为 0，可用 `--camera-device-index 1` 选择第二台；请先退出占用同一相机的感知程序。无力录制的采集覆盖手动拖动过程；回放的采集覆盖回到起点和轨迹回放两个阶段。自然完成、手动停止、断开或退出时会关闭文件和相机。相机或图片写入出错时，无力录制会保存已有轨迹并继续保持失能，回放会停止并保持当前位置；机械臂本身故障仍走原有失能流程。

每次同步采集新建 `apps/control/runtime/calibration/playback_时间戳/`，页面可指定其他新目录，已有目录不会覆盖：

```text
playback_时间戳/
  rgb/000000.png             # 原始彩色帧，无叠加、无去畸变
  frames.jsonl               # 每张图片及其对齐的实测关节位置
  joints.jsonl               # 带时间戳的原始关节反馈
  session.json               # 相机内参/畸变、设备信息、机器人配置、时钟说明
  source_trajectory.json     # 仅回放模式：本次回放使用的原始轨迹
  summary.json               # 图片数、有效对齐数、结束原因、错误
```

无力录制的关节轨迹仍保存到页面的“录制保存路径”；`session.json` 的 `joint_recording_path` 记录该路径，`capture_mode` 区分 `recording` 与 `playback`。两种模式均使用 `frames.jsonl` 配对图片与关节，无需用轨迹 JSON 的相对时间推算。

RGB 为 640×480、30 FPS，保存为无额外压缩损失的 PNG；相机自身的 MJPG 解码损失仍然存在。图像没有应用去畸变，可在后续标定时使用 `session.json` 中的 `camera.K` 和 `camera.distortion`。设备内参是 SDK 提供的初始值，并非本次重新标定所得。安装仅使用 SDK 的原生绑定，不安装其 Open3D/OpenCV 等示例程序依赖。

`frames.jsonl` 每行是一张图：`rgb_path` 为图片相对路径，`positions_rad` 为与该图对齐的 **实测** J1–J7 **电机原始**弧度角（未经关节补偿；`session.json` 的 `joint_compensation` 记录采集时生效的方向与零点，离线使用前须按它换算成模型角度），`alignment_valid` 表示是否可用于后续配对。它使用相机帧到达主机的单调时钟时间，在前后两条机械臂反馈之间线性插值；每侧时间差不得超过 50 ms。缺少前后反馈或间隔过大的帧仍保留图片，但其 `positions_rad` 为 `null`，必须在标定时剔除。`joint_timestamps_monotonic`、`joint_time_offsets_sec` 和 `interpolation_alpha` 保留插值依据。`playback_phase` 区分 `return_to_start`、`trajectory` 和保持阶段；需要时可仅选择轨迹阶段。

`joints.jsonl` 按底层控制频率约 100 Hz 读取 SDK 缓存，重复时间戳不重复写入；采样不额外占用 CAN。RGB 和写盘在独立线程进行。`timestamp_monotonic` 的单位是秒，所有主机时间在同一时钟域；相机原始设备时间和系统时间另存为微秒字段，不直接当成该时钟域使用。SDK 对关节位置与反馈时间做加锁快照，避免读到一半更新的数据。

这是**软件时间对齐**，不是曝光硬件触发同步。USB/驱动缓冲延迟、曝光时长和 CAN 顺序读取关节的时间差仍然存在，文件中的时间差也不等同于实际曝光同步误差。高精度动态标定需要进一步测量时间偏移或加入硬件同步；当前采集更适合低速移动、静止姿态附近选帧。显式模拟模式使用明确标记 `mock=true` / `synthetic=true` 的合成图片，仅供流程测试，不能作为真机标定数据。

采集结果位于已有 `.gitignore` 覆盖的 `runtime/` 下，不会随源码提交。页面显示图片数、有效对齐数和实际保存目录；需要纯关节回放时可关闭同步采集开关。

手眼标定不再使用这里的同步采集数据，而是用 [`../charuco_handeye/README.md`](../charuco_handeye/README.md) 中的专用采集程序：每个姿态电机出力保持静止，再同时记录关节平均值和图像，避免运动中软件时间对齐带来的误差。

## 结构与验证

- `app.py`：Viser 页面、模型反馈和更新循环（本目录）。
- `gx4m_real/robot/arm.py`：独立的模拟/真机 PVT 控制，不包含手套、Tracker、IK、相机或策略逻辑。
- `gx4m_real/robot/config.py`：硬件限位、关节映射和配置加载。
- `gx4m_real/robot/trajectory.py`：带时间戳的关节录制文件保存、加载与校验。
- `gx4m_real/robot/recorder.py`：无力录制和回放时的 RGB 采集、关节反馈插值和标定数据写入。
- `gx4m_real/camera/orbbec.py`：`OrbbecColorCamera`，Gemini 原始彩色图和 SDK 内参。
- `third_party/libgx7/`：源项目驱动的本地副本，包括动态库；来源记录在 `SOURCE.json`。SDK 内部保留原有模块，不需要安装原 tracker 应用，也不需要它的目录仍然存在。

`setup.sh` 会以可编辑模式安装 `third_party/libgx7` 和仓库根目录的 `gx4m_real` 包。

运行无需硬件的测试：

```bash
conda activate gear3_control
python -m unittest discover -s apps/control/tests -v
```

验证包括：模拟模式不访问硬件、首条真机命令使用实测位置、目标显式提交、限位和非有限数值校验、反馈超时阻止后续命令、断开释放资源、模型与固定手指的关节映射，以及失能采集、保存和加载、回放起点对齐与速度限制、故障保存。真机分支用替代驱动验证；未进行真实机械臂运动测试。

2026-10-28 实测：11 项自动测试通过，浏览器完成连接、编辑滑块、发送、保持和断开检查，三维模型正常显示，页面无 JavaScript 异常。独立环境的依赖一致性检查通过。

本次加入录制与回放后，17 项自动测试全部通过，并完成模拟模式的页面对象录制、保存、加载回放和停止流程检查；未连接真机。

加入 RGB 同步采集后，29 项自动测试通过，覆盖实测关节插值、无效对齐标记、RGB 文件颜色与索引一致性、采集异常、回放完成和手动停止后的收尾。相机 SDK 原生绑定导入检查通过；未打开真实相机或驱动机械臂。
