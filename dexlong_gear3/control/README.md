# GX7＋GX4M 关节控制

单页 Viser 控制台，只控制 GX7 右臂 J1–J7。GX4M 手和腕部相机保留在模型中，手指固定为 `config/initial_pose.json` 的姿态，不连接其硬件。

## 安装与启动

在仓库根目录执行：

```bash
bash dexlong_gear3/control/setup.sh
bash dexlong_gear3/control/run.sh
```

打开 **http://127.0.0.1:8086**。默认是模拟模式，启动时未连接；点击“连接”后可以操作。模拟模式不会导入或打开 CAN 驱动。

1. 移动 7 个滑块编辑目标角度，单位为度；此时模型和机械臂不移动。
2. 点击“发送目标”提交整组角度。模型按实际反馈更新，下面的表格显示实际角度和已提交目标。
3. “保持当前位置”取消尚未完成的目标，改为保持当前实测位置，同时把滑块同步到该位置。
4. “断开”释放连接；终端 Ctrl+C 会清理控制线程和 Viser 服务。

`run.sh` 从任意工作目录均可运行。安装脚本只创建独立的 `gear3_control` Conda 环境并安装依赖，不连接机械臂，不修改感知环境。Python 入口也可直接运行：

```bash
conda activate gear3_control
python dexlong_gear3/control/app.py
```

## 真机模式

```bash
bash dexlong_gear3/control/run.sh --real
```

真机模式也以未连接状态启动，只有点击“连接”才打开 CAN 并使能右臂。连接先读取实测位置，以该位置初始化 PVT 目标，再启动控制线程；不会自动回零或前往初始姿态（`config/initial_pose.json`）。断开或退出会调用原 SDK 的停止流程，停止线程并失能电机；这与“保持当前位置”不同，断开前应托住需要支撑的机械臂。

`config.yaml` 的默认值来自源项目配置：适配器序列号 `31F1000632C`，CAN1／通道 0。请按实际接线修改；指定序列号不存在时直接报错，不回退到其他适配器。页面滑块和发送校验采用 `gx7_right.yaml` 的硬件限位，电机 1–7 明确映射到模型 `joint1`–`joint7`。角度在驱动内部为弧度。

默认底层控制 100 Hz，目标和界面更新约 30 Hz，速度上限 0.25 rad/s，力矩比例上限 0.85，每次目标与实测关节的差值限制为 0.08 rad。保留底层软限位、电机故障保护及 CAN 超时处理；反馈超过 0.3 秒未更新时进入故障并停止驱动，需断开再连接。

## 无力录制与位置回放

启动方式不变，在页面“无力录制与位置回放”中操作：

1. 连接后先托住机械臂，点击“开始无力录制”。J1–J7 失能、不出力，可以手动拖动；页面模型跟随实测位置。驱动器必须持续供电，CAN 必须保持连接。
2. 点击“停止并保存录制”，将约 30 Hz 的关节反馈和相对时间保存为 JSON。默认路径为 `control/runtime/recordings/joints_时间戳.json`，也可修改保存路径；已有文件不会被覆盖。停止后继续保持失能。
3. 保存路径会自动填入“回放文件路径”。也可以填入以前保存的 JSON 文件绝对路径。点击“开始位置回放”，恢复出力，先限速移动到录制起点，再按时间顺序插值回放。结束后保持最后位置。
4. “回放倍率”范围为 0.1–2 倍；程序会按原有 0.25 rad/s 速度上限自动降低实际倍率。实测位置落后时暂停推进轨迹时间，因此回放用时可能比录制更长。
5. 点击“停止回放并保持”可中止回放；失能状态下点击“保持当前位置”会恢复出力并保持当前实测姿态。

正常断开、Ctrl+C 或反馈故障会尝试保存已录制的数据；进程被强制杀死或掉电时，尚未保存的数据会丢失。JSON 使用 `joint1`–`joint7` 顺序、弧度和秒，加载时会校验关节顺序、角度限位、有限数值和时间递增。一次有效回放至少需要两帧。

失能采集使用 SDK 的失能指令回复读取编码器反馈，CAN 收发统一在底层控制线程执行；失能期间不发送位置目标或使能指令。该路径已通过模拟驱动测试，仍需在实机上确认失能回复中的角度会随手动拖动持续更新。模拟模式支持完整录制、保存、加载和回放流程，但不会自行生成手动拖动动作。

模型使用本仓库 `asset/gx7_right/urdf/gx7_right_gx4m_cam_xl330.urdf`，基座和固定手指姿态取自 `config/initial_pose.json`。默认仅监听本机，地址和端口可在 `config.yaml` 修改，亦可通过 `--config` 指定另一份配置。

## 回放时同步采集 RGB 与关节位置

页面“回放同步采集 RGB 与关节位置”的开关默认开启。更新后先运行一次安装脚本，补齐相机 SDK；启动命令不变：

```bash
bash dexlong_gear3/control/setup.sh
bash dexlong_gear3/control/run.sh --real
```

选择关节轨迹并点击“开始位置回放”，程序先打开 Gemini / Orbbec 相机并预热，确认有 RGB 图像后才开始运动。相机默认设备索引为 0，可用 `--camera-device-index 1` 选择第二台；请先退出占用同一相机的感知程序。采集覆盖回到起点和轨迹回放两个阶段，自然完成、手动停止、断开或退出时会关闭文件和相机。相机或图片写入出错时会停止回放并保持当前位置；机械臂本身故障仍走原有失能流程。

每次回放新建 `control/runtime/calibration/playback_时间戳/`，页面可指定其他新目录，已有目录不会覆盖：

```text
playback_时间戳/
  rgb/000000.png             # 原始彩色帧，无叠加、无去畸变
  frames.jsonl               # 每张图片及其对齐的实测关节位置
  joints.jsonl               # 带时间戳的原始关节反馈
  session.json               # 相机内参/畸变、设备信息、机器人配置、时钟说明
  source_trajectory.json     # 本次回放使用的原始轨迹
  summary.json               # 图片数、有效对齐数、结束原因、错误
```

RGB 为 640×480、30 FPS，保存为无额外压缩损失的 PNG；相机自身的 MJPG 解码损失仍然存在。图像没有应用去畸变，可在后续标定时使用 `session.json` 中的 `camera.K` 和 `camera.distortion`。设备内参是 SDK 提供的初始值，并非本次重新标定所得。安装仅使用 SDK 的原生绑定，不安装其 Open3D/OpenCV 等示例程序依赖。

`frames.jsonl` 每行是一张图：`rgb_path` 为图片相对路径，`positions_rad` 为与该图对齐的 **实测** J1–J7 弧度角，`alignment_valid` 表示是否可用于后续配对。它使用相机帧到达主机的单调时钟时间，在前后两条机械臂反馈之间线性插值；每侧时间差不得超过 50 ms。缺少前后反馈或间隔过大的帧仍保留图片，但其 `positions_rad` 为 `null`，必须在标定时剔除。`joint_timestamps_monotonic`、`joint_time_offsets_sec` 和 `interpolation_alpha` 保留插值依据。`playback_phase` 区分 `return_to_start`、`trajectory` 和保持阶段；需要时可仅选择轨迹阶段。

`joints.jsonl` 按底层控制频率约 100 Hz 读取 SDK 缓存，重复时间戳不重复写入；采样不额外占用 CAN。RGB 和写盘在独立线程进行。`timestamp_monotonic` 的单位是秒，所有主机时间在同一时钟域；相机原始设备时间和系统时间另存为微秒字段，不直接当成该时钟域使用。SDK 对关节位置与反馈时间做加锁快照，避免读到一半更新的数据。

这是**软件时间对齐**，不是曝光硬件触发同步。USB/驱动缓冲延迟、曝光时长和 CAN 顺序读取关节的时间差仍然存在，文件中的时间差也不等同于实际曝光同步误差。高精度动态标定需要进一步测量时间偏移或加入硬件同步；当前采集更适合低速移动、静止姿态附近选帧。默认模拟模式使用明确标记 `mock=true` / `synthetic=true` 的合成图片，仅供流程测试，不能作为真机标定数据。

采集结果位于已有 `.gitignore` 覆盖的 `runtime/` 下，不会随源码提交。页面显示图片数、有效对齐数和实际保存目录；需要纯关节回放时可关闭同步采集开关。

采集完成后，可直接使用 [`../charuco_handeye/README.md`](../charuco_handeye/README.md) 中的离线标定入口读取这个目录，无需手动整理图片或重新输入关节角。它支持固定相机和腕部相机两种模式，并用 Viser 显示标定后的相机、标定板和机器人位姿。

## 结构与验证

- `app.py`：Viser 页面、模型反馈和更新循环。
- `arm.py`：独立的模拟/真机 PVT 控制，不包含手套、Tracker、IK、相机或策略逻辑。
- `config.py`：硬件限位、关节映射和配置加载。
- `trajectory.py`：带时间戳的关节录制文件保存、加载与校验。
- `calibration.py`：Gemini RGB 采集、关节反馈插值和标定数据写入。
- `vendor/libgx7/`：源项目驱动的本地副本，包括动态库；来源记录在 `SOURCE.json`。SDK 内部保留原有模块，不需要安装原 tracker 应用，也不需要它的目录仍然存在。

运行无需硬件的测试：

```bash
conda activate gear3_control
python -m unittest discover -s dexlong_gear3/control/tests -v
```

验证包括：模拟模式不访问硬件、首条真机命令使用实测位置、目标显式提交、限位和非有限数值校验、反馈超时阻止后续命令、断开释放资源、模型与固定手指的关节映射，以及失能采集、保存和加载、回放起点对齐与速度限制、故障保存。真机分支用替代驱动验证；未进行真实机械臂运动测试。

2026-10-28 实测：11 项自动测试通过，浏览器完成连接、编辑滑块、发送、保持和断开检查，三维模型正常显示，页面无 JavaScript 异常。独立环境的依赖一致性检查通过。

本次加入录制与回放后，17 项自动测试全部通过，并完成模拟模式的页面对象录制、保存、加载回放和停止流程检查；未连接真机。

加入 RGB 同步采集后，29 项自动测试通过，覆盖实测关节插值、无效对齐标记、RGB 文件颜色与索引一致性、采集异常、回放完成和手动停止后的收尾。相机 SDK 原生绑定导入检查通过；未打开真实相机或驱动机械臂。
